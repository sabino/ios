The second consecutive 720-second phone run used the same staged kernel,

`d3016b5e1cda3e968528ad076ab7343f4c591abb34bd67ed48b6a9554f419137`,

Jumpdrive then read 26% / 3.735 V, Charging. Thus two consecutive timed
phone boots passed the storage integrity gate without a manual reset or
data repair. Both observed zero overflow uses, so the overflow path remains
